# 08. 测试与一致性验收

## 1. 测试目标

迁移不是以“页面能打开”为完成标准，而是以业务结果、用户数据和主要交互与旧版本一致为标准。

## 2. 测试层次

### 单元测试

- 数据解析。
- 内存索引。
- 等级曲线。
- 品质、星锻和超越。
- 附魔规则。
- 技能限制。
- checksum。
- 文件格式。
- 数据库迁移。
- 随机数生成器。

### Golden 测试

使用相同 JSON 输入，对比 Rust 已知输出与 TypeScript 输出：

- 英雄属性。
- 勇士属性。
- 装备属性。
- 泰坦环境。
- 模拟结果。

### 集成测试

- 加载真实 content。
- 保存和重新加载体系。
- 导出再导入。
- 完整备份再恢复。
- 数据版本升级。
- Worker 进度和取消。

### E2E 测试

- 创建体系。
- 添加英雄。
- 选择技能。
- 穿戴六槽装备。
- 切换星锻和超越。
- 选择两种附魔。
- 编辑勇士。
- 切换勇士之魂和泰坦之塔/墓。
- 建立冒险任务。
- 执行和取消模拟。
- 导出与导入。

### 视觉测试

对关键页面进行固定尺寸截图比较。

## 3. Golden Fixture 规则

fixture 必须：

- 使用 JSON。
- 不依赖 Rust 序列化才能读取。
- 明确记录来源。
- 明确记录游戏数据版本。
- 固定随机 seed。
- 不包含用户凭据和机器路径。

建议结构：

```text
tests/golden/
├── calculations/
├── champions/
├── equipment/
└── simulations/
```

## 4. 关键边界用例

- 英雄等级 1、5、40、50。
- 最大英雄阶数。
- 种子 0 和上限。
- 卡片等级 0 和上限。
- 技能未解锁、刚解锁和满级。
- 装备 T1、T16。
- 普通和传说品质。
- 无星锻、满星锻。
- 无超越、开启超越。
- 内置与替换附魔。
- 勇士之魂开关。
- 泰坦之塔/墓开关。
- 两个开关独立组合。
- 模拟迭代 1、100、10,000。

## 5. CI 门禁

每次提交必须运行：

```bash
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run content:validate
npm run build
```

任何 golden 差异必须人工确认，不能简单更新预期值绕过失败。

## 6. 上线验收

- 直接访问首页返回 200。
- 刷新任意前端路由返回应用页面。
- 所有静态资源返回正确 MIME。
- 控制台无未处理错误。
- 网络面板没有 `localhost` 和远程第三方运行时请求。
- HTTPS 下 Clipboard 和 Service Worker 正常。
- 断网后缓存版本可以启动。

## 7. 完成条件

- 单元测试全部通过。
- golden 测试全部通过。
- 核心 E2E 全部通过。
- 关键视觉截图通过人工验收。
- Nginx 生产环境通过冒烟测试。
