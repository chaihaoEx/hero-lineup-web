# 01. 迁移目标与范围

## 1. 总目标

将现有 `hero-lineup` 桌面应用完整迁移到独立目录 `hero-lineup-web`，形成可直接静态部署的纯 Web 应用。

最终交付物：

```text
hero-lineup-web/dist/
├── index.html
├── assets/
├── content/
├── manifest.webmanifest
└── service-worker.js
```

该目录可以直接复制到 Nginx、对象存储或静态站点服务中运行。

## 2. 必须实现的业务范围

### 英雄

- 职业选择和职业默认技能。
- 英雄等级、阶数、种子和卡片等级。
- 自带技能、四个技能槽、技能等级和等级上限。
- 职业、技能家族、技能分类和重复技能限制。
- 六槽装备和对应装备类型限制。
- 实时属性计算。

### 勇士

- 勇士列表、头像和基础配置。
- 勇士等级、阶数、种子、卡片等级。
- 勇士之魂。
- 熟悉物和光环乐曲等勇士装备。
- 泰坦之塔/墓环境开关及独立计算。
- 实时属性计算。

### 装备

- 装备槽位、品质、阶数和排序。
- 星锻、超越、元素附魔和精萃附魔。
- 内置附魔与可替换附魔规则。
- 职业、等级和装备类型限制。
- 装备数量统计和需求清单。

### 冒险

- 任务分组和排序。
- 成员选择与队伍限制。
- 普通、精英、泰坦塔和泰坦墓规则。
- 指定随机种子的确定性模拟。
- 模拟进度、取消、结果详情和历史记录。

### 本地数据

- 体系、配装模板和用户设置持久化。
- `.zyslineup` 导入导出。
- `.zysbackup` 完整备份与恢复。
- PNG 导出和剪贴板交互。
- 数据版本兼容检查。

## 3. 非目标

第一阶段不实现：

- 用户账号和登录。
- 云端数据库。
- 多设备自动同步。
- 多人实时协作。
- 服务端短口令。
- 服务端计算。
- 管理后台。
- 浏览器运行时动态调用 Rust。

六位线上短口令依赖服务器保存映射，纯静态应用只能识别包含完整数据的配置口令或文件。

## 4. 质量目标

- 页面主要布局和交互不因迁移退化。
- 同一输入在原 Rust 版和新 TypeScript 版得到一致结果。
- 10,000 次冒险模拟不阻塞主线程。
- 页面刷新、浏览器重启和应用升级后数据不丢失。
- 完成缓存后可断网启动。
- 浏览器运行期间不连接 `localhost`，也不监听任何端口。
- 生产构建不包含 Tauri、Rust 或仅供测试的预览结果。

## 5. 完成定义

同时满足以下条件，才算完成整体迁移：

1. `hero-lineup-web` 可以独立安装、测试和构建。
2. 删除 Rust/Tauri 环境后仍能完成全部 Web 构建与测试。
3. Nginx 只托管 `dist/` 即可运行全部核心功能。
4. 计算和模拟 golden cases 全部通过。
5. 导入导出能在桌面旧版和 Web 新版之间双向兼容。
6. Playwright 覆盖主要用户流程。
7. 线上环境通过 HTTP、HTTPS、缓存和刷新测试。
