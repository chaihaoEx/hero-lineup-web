# 04. 属性计算引擎迁移

## 1. 目标

将原 Rust `hero-catalog` 和 Tauri command 中的属性计算迁移为纯 TypeScript，并保证结果一致。

现有浏览器预览公式不能作为最终实现。

## 2. 计算范围

### 英雄基础数据

- 职业基础属性。
- 1–50 级成长。
- 英雄阶数。
- 三类种子分配。
- 卡片等级。
- 英雄元素值。

### 技能

- 职业自带技能。
- 四个可选技能槽。
- 技能解锁等级。
- 技能等级和上限。
- 技能家族互斥。
- 技能分类互斥。
- 职业和类型限制。
- 普通、满级和元素门槛效果。

### 装备

- 六个英雄装备槽。
- 勇士熟悉物和光环乐曲。
- 装备类型和职业限制。
- 装备阶数与英雄等级限制。
- 品质倍率。
- 星锻倍率。
- 超越倍率和固定加成。
- 装备内置元素、精萃。
- 可选元素和精萃附魔。
- 附魔亲和与上限。
- 附魔技能加成。

### 勇士

- 勇士等级曲线。
- 阶数成长。
- 泰坦勇士修正。
- 勇士之魂。
- 泰坦之塔/墓环境。
- 卡片和种子。
- 最终元素值。

## 3. 推荐计算管线

```text
读取并验证输入
→ 解析职业/勇士记录
→ 计算基础属性
→ 应用等级和阶数
→ 应用种子
→ 解析技能
→ 解析装备
→ 应用品质
→ 应用星锻
→ 应用超越
→ 应用附魔
→ 应用卡片
→ 应用环境修正
→ 取整和输出
```

每个阶段使用独立纯函数，不允许在一个巨大函数中修改共享对象。

## 4. 数值规则

迁移时必须逐条记录：

- 使用 `round`、`floor` 还是截断。
- 百分比的计算顺序。
- 固定值与百分比的先后顺序。
- 叠加使用加法还是乘法。
- 装备属性的上限。
- 浮点误差处理方式。

JavaScript 数值与 Rust 浮点行为接近，但取整位置不同会造成明显误差。每个历史问题都应增加回归用例。

## 5. 输出结构

计算函数返回：

```ts
interface CalculatedSheet {
  stats: CalculatedStats;
  issues: CalculationIssue[];
  applied: AppliedRules;
}
```

除最终属性外，还必须提供：

- 错误。
- 警告。
- 被应用的规则。
- 装备或技能被拒绝的原因。
- 便于 UI 显示的属性增量。

## 6. 迁移策略

1. 从 Rust 测试提取输入与预期结果。
2. 转换为语言无关 JSON fixture。
3. 在 TypeScript 中建立同一 golden test。
4. 实现最小公式直到测试通过。
5. 补充线上页面人工样例。
6. 完成所有边界值后替换浏览器预览计算。

禁止先删除旧 Rust 测试再迁移。

## 7. 性能要求

- catalog 只加载一次。
- 计算使用 Map 索引。
- 单次英雄或勇士计算在普通电脑上应明显低于 16ms。
- 连续修改装备时不得重复解析全部 JSON。
- React 状态变化不应导致全目录重建。

## 8. 验收条件

- 原 Rust golden cases 在 TypeScript 中全部通过。
- 英雄等级 1、40、50 等边界一致。
- 装备 T1、T16、星锻和超越样例一致。
- 勇士之魂与泰坦之塔/墓保持独立。
- 相同配置的最终属性逐字段一致。
- 不再使用 `browser-preview` 结果。
